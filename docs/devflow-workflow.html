Git-native · Local-first

Từ yêu cầu đến code đã land.

Một workflow có đường đi rõ ràng cho cả task nhỏ lẫn change lớn: xếp hàng, claim bằng worktree, kiểm tra bằng gate và giữ đầy đủ dấu vết trong Git.

queue → branch 1 task = 1 nhánh = 1 land gate before land

Nhớ 5 việc là đủ

  1. Đưa việc vào queue
  2. Chọn task không còn blocker
  3. Claim bằng branch + worktree
  4. Code, ship, check, land
  5. Đóng queue; archive nếu có spec
Nguồn sự thật: Git + file Markdown trong repo.

01 / OVERVIEW

Một đường đi, bảy điểm kiểm soát

Agent không nhảy thẳng vào code. Mỗi thay đổi đi qua cùng một vòng đời; độ lớn của task chỉ quyết định mức tài liệu cần có.

01

Intake

Làm rõ yêu cầu, phạm vi và tiêu chí hoàn tất.

02

Ready

Chỉ chọn việc không còn blocker, theo thứ tự ưu tiên.

queue next
03

Claim

Một lệnh: đánh dấu In progress và tạo branch/worktree riêng. Nhận trùng sẽ bị từ chối.

queue start --branch
04

Plan

Task nhỏ plan trong chat; change lớn dùng OpenSpec.

proposal → tasks
05

Build

Code theo lát nhỏ, commit nhỏ trong nhánh; cả nhánh land một lần.

feat: / fix:
06

Verify

Ship, check và chạy gate thay cho niềm tin cảm tính.

ship → check
07

Land, close & untask

Fast-forward vào dev, đóng queue, archive change nếu có rồi gỡ worktree bằng luồng chuẩn.

land → done → archive → untask
02 / ROUTING

Chọn độ sâu, không đổi nguyên tắc

Bấm để xem đường đi phù hợp. Task lớn thêm lớp spec; còn queue, worktree, gate và land vẫn giữ nguyên.

1. QueueMột dòng mô tả là đủ
2. ClaimBranch + worktree riêng
3. PlanKế hoạch ngắn trong chat
4. CodeTest và commit gọn
5. LandGate xanh rồi đóng queue

Không có tasks.md. Nếu việc phình ra hoặc xuất hiện nhiều quyết định thiết kế, hãy nâng thành OpenSpec change thay vì cố giữ nhãn “nhỏ”.

1. QueueTrỏ tới thư mục change
2. Specproposal + design
3. Taskstasks.md có thứ tự
4. BuildMỗi task một commit
5. ArchiveSau khi đã land vào dev

Chi tiết nằm đúng một nơi: openspec/changes/<change>/tasks.md. Queue chỉ giữ một dòng mục lục, không sao chép checklist.

05 / WAITING

Task bị chặn thì park, không bỏ quên

Handoff biến trạng thái trong đầu agent thành dữ liệu có thể tiếp tục ở session sau.

Khi bị chặn

  • Chạy /devflow:handoff
  • Ghi rõ đã xong gì, đang chờ gì
  • Ghi lệnh test và bước tiếp theo
  • Commit handoff lên nhánh task
  • queue block --reason
→

Khi được unblock

  • Quay lại đúng worktree
  • Chạy /devflow:handoff resume
  • Kiểm tra thay đổi chưa commit
  • Chạy lại lệnh test trong note
  • Làm tiếp từ mục “Tiếp theo”

07 / WORKTREE CLEANUP

Dọn worktree kẹt — chỉ sau land và untask

npm run worktrees:clean là đường cứu hộ khi npm run untask hoặc ExitWorktree không gỡ được worktree. Có thể chạy từ main checkout hoặc một worktree của repo; script tự chuyển về main checkout trước khi xử lý.

Khi nào cần dùng?

  • Còn thư mục sau lỗi Permission denied.
  • ExitWorktree báo No-op vì worktree thuộc session cũ.
  • Còn thư mục dưới .claude/worktrees/ nhưng Git không còn biết tới.

Đúng thứ tự

Luôn thử luồng chuẩn trước. Chỉ chuyển sang cleanup khi worktree vẫn còn sót.

land→untask→worktrees:clean
DRY RUN · KHÔNG ĐỔI GÌ

Kiểm tra toàn bộ

npm run worktrees:clean

Liệt kê mọi worktree và thư mục, rồi đánh dấu an toàn hoặc rủi ro.

XÓA MỤC AN TOÀN

Dọn tự động

npm run worktrees:clean -- --yes

Xóa cây sạch có nhánh đã vào dev, thư mục mồ côi và đăng ký worktree đã stale; nhánh đã merge cũng được xóa.

GIỚI HẠN PHẠM VI

Chỉ dọn một mục

npm run worktrees:clean -- --yes <tên>

Chỉ xử lý mục khớp tên nhánh hoặc tên thư mục. Có thể truyền nhiều tên trong cùng lệnh.

RỦI RO · MẤT DỮ LIỆU

Buộc xóa

npm run worktrees:clean -- --yes --force

Xóa cả cây có thay đổi chưa commit hoặc nhánh chưa vào dev, đồng thời xóa nhánh bằng -D. Chỉ dùng khi chấp nhận mất phần việc đó.

Nếu vẫn gặp EPERM: đóng terminal, cửa sổ IDE hoặc Claude Code session đang đứng trong thư mục cần xóa rồi chạy lại. Script gỡ junction/symlink như node_modules và .husky/_ trước khi xóa để không đi theo liên kết sang main checkout.

08 / GUARDRAILS

Workflow tốt là workflow khó đi sai

Guard hook và gate biến quy ước thành kiểm tra có thể lặp lại — thay vì trông chờ agent nhớ mọi luật.

G1

Không phá protected branch

Chặn checkout cưỡng bức, merge tay và reset hard trên nhánh được bảo vệ.

G2

Gate trước khi land

Lint, test và hard-rules phải xanh. Land theo fast-forward-only để lịch sử thẳng.

G3

Commit có ngữ nghĩa

Conventional Commits, commitlint chạy từ binary local; commit nhỏ trong nhánh, một task land một lần.

Luật kết thúcTask nhỏ: land → queue done → untask. Change lớn: land → queue done → /opsx:archive → untask (/opsx:apply và /opsx:archive chạy ở phiên mới). Không archive trước khi code đã vào dev.

Queue nói “làm gì”. Git nói “ai đang làm”. Gate nói “đủ tốt chưa”.

Ba lớp này tách trách nhiệm rõ ràng, nên cùng một workflow có thể dùng cho một agent, nhiều agent, task nhỏ hoặc change dài ngày.
